## 1. Where we got to

RuvNet-Brain is a per-machine intelligence layer that watches your rUv/AI stack, notices when something
you already installed has gone dormant or misconfigured, and tells you — with a one-click fix it can also
reverse. It grew up a **reactive** tool (answer when asked) and this release is the attempt to make it
**proactive** (speak at the right moment) and **compounding** (learn across projects).

On ADR-028's five-rung proactivity ladder:

- **L0 Reactive, L1 Observant, L2 Advocating — shipped and working.** The knowledge battery is 60/60; the
  console renders real machine faults with real execute-and-undo. This is the honest, provable floor.
- **L3 Contextual (speak in-session, no page to visit) — its machinery was built this session, and is
  deploy-gated.** The chokepoint (ADR-040) makes one runtime own every user-facing byte and routes the
  in-session producers through it; the fixture machine (ADR-041) makes the surface's accuracy measurable.
  But the spine that actually runs on the machine is still the older `3.9.18` — so *today, live, the
  experience is still L2 (console-only) plus the old nag.*
- **L4 Anticipatory (infer the goal, name the better path first) — a wired surface exists, unproven to spec, and the first redesign was rejected.** `goal-match.mjs` ("the L4 surface") is imported by `anticipate.sh:77`; what is missing is proof it meets ADR-028's L4 bar (names the better path *before* you commit) at the five-test-class standard. The first redesign attempt (ADR-045, state-based advocacy) was **REJECTED by both duelists** on 2026-07-24 — the core finding being that *detection is a precondition, not a parallel track*, and the ADR's own motivating example was a false alarm. The rewrite spec is recorded in the ADR; L4 goes back through the recipe.
- **L5 Compounding (promote validated lessons globally) — miner only; nothing promoted yet.**

**The honest summary: we built to the fence line.** Almost everything reachable behind a
branch-only-no-push constraint is done; the rest requires deployment and real usage, which are owner
decisions, not more code.

## 2. The philosophy of Proactive

**The thesis, in one line:** *a page you have to visit is not proactivity — it is a dashboard with better
copy.* The proof that made this concrete: the brain had everything it needed to say *"36 stores embedded,
never distilled — 6,858 memories teaching nothing"* for **21 days** before anything said it. Nothing was
*structurally obliged to speak*. Destroying that 21-day latency is the entire point of the release.

Proactivity is therefore defined as a **testable ladder**, not an adjective — each rung a falsifiable
claim (L3: a relevant dormant capability surfaces in-session with no page opened; L4: the better path is
named before you commit to the worse one; L5: a lesson from project A changes behavior in project B).

And it is bounded by four **anti-goals**, because proactivity destroys itself faster than it helps:

- **No nagging** — a recommendation fires once per state change, is dismissible, and never re-fires while
  dismissed. Frequency is a feature with a hard ceiling, not a dial to turn up.
- **No evangelism** — this is *goal-aware capability matching*, not selling rUv. Recommending a tool to
  someone whose problem it doesn't fit is the same failure, faster, because it's indistinguishable from
  salesmanship.
- **No interruption without an off switch** — anything that speaks in-session must be silenceable in one
  action, permanently, without penalty.
- **No fabricated urgency** — severity comes from measured evidence on *this* machine, never from what
  would be good for adoption.

**The governing principle, in the owner's words:** *"Nudging somebody is very fair. Forcing them through
a gate is not."* This is why the in-session speech is a nudge (advisory, exit 0, never refuses) and
blocking is a narrow exception a user opts a *specific* rule into.

## 3. The philosophy of Learning

**The thesis:** *a lesson that does not survive an update was never global.* Learning is not "store text";
it is **mine → validate → promote → survive → change behavior elsewhere**. The measure of it is the
**compounding rate**: lessons promoted to global ÷ lessons learned, and survival across a refresh must be
100%. Anything less is a notebook, not a brain.

Two philosophical commitments shape it, and both were tested this session:

- **A ratified lesson is the user's own words, not the brain's advocacy.** They are different *consent
  categories*. This is why lessons never go under the "advocacy volume" dial — putting the user's own
  opted-in words under a knob that governs what the brain *volunteers* is a modelling error. (Fable 5
  caught exactly this error in a first design and it was corrected — see §11.)
- **Nudge, never force — even for lessons.** A promoted lesson *reminds* you a few times, then trusts
  you (the per-session cap), and only *refuses* if you explicitly opted that specific rule into blocking.

**The honest state of the philosophy vs the build:** the philosophy is fully specified and the miner is
real (736 lessons, 41 projects, 7 promotable, each citing its sources). But the **loop has never closed
once** — nothing is promoted, so survival across an update has never been demonstrated. The idea is
complete; the empirical proof is at zero.

## 4. How the two integrate

This is the hinge of the whole release, so it gets stated plainly:

> **Proactive advocacy produces outcomes → outcomes become evidence → evidence becomes lessons → lessons
> compound globally → and compounded lessons make the next advocacy sharper.**

Concretely: every recommendation the brain makes is logged as *offered / dismissed / applied* in the
advocacy ledger. That ledger is what turns "we recommended X" into **precision** (was it acted on?) — and
the recommendations that were *right* are exactly the raw material Learning promotes. A brain that
advocates but never learns whether it was right is a nag; a brain that learns but never advocates is a
library. The integration is what makes it a *compounding* system.

**And here is the most honest sentence in this briefing:** that integration is **architecturally complete
and empirically unstarted.** The wiring exists; the ledger exists as a file — but it holds exactly **one
synthetic self-test row** (`f-adv-1`, `hash-1`), so precision is computable and *meaningless*. The loop
has never turned on real data. That is not a bug; it is the deploy-gated ceiling, and naming it is the
difference between this briefing and a pitch.

## 6. What was actually done (this arc)

Delivered behind the hard fence (branch only, nothing pushed), each with a test shaped to fail on the
un-fixed code:

- **The chokepoint (ADR-040, `.33`).** One runtime (`unprompted-runtime.mjs`) owns every user-facing byte
  via *captured* child stdio, with a per-channel policy (advocacy obeys the dial + dismissal ledger;
  lessons keep their own cap and never touch the dial; alarms always pass). A registry test *fails* if any
  emitter is ever wired to speak off-runtime — proven by adding a rogue emitter and watching it fail.
- **The fixture machine (ADR-041, `.32` → refuted → repaired `2c8ef4d`).** The `.32` build *claimed*
  recall/false-alarm were real; GPT-5.6-Sol's REJECT proved the oracle had copied the detector's own
  regex (the echo trap), and the numbers were retracted. The repair made the oracle **structural +
  referential** (a capture command wired at both boundaries invoking a script that really exists —
  grounded in agentic-flow's context-persistence hook and ruv-fann's session-end pattern, never the
  detector's rule). **Re-measured 2026-07-24: recall 1.00, false-alarm 0** on the 2-capability cohort,
  with **mutation tests proving both numbers fall on a broken detector.** 2 of 5 acceptance metrics are
  now genuinely measured — and the path there (assert → refute → retract → repair → re-measure) is
  itself the QA discipline working.
- **The continuation gate hardened (`.36`, ADR-043)** and **the chokepoint hardened (`.37`, ADR-040)** —
  in both cases the REAL GPT-5.6-Sol found REJECT-level bugs by *running* the code that design-only
  review had missed (for the chokepoint: channel-spoofing, fail-open on producer error, and pipe-byte
  truncation — all fixed, 21 chokepoint tests).
- **The detector's two false positives fixed (`.38`)** — "dormant" now means installed **+ usable +
  never used**, killing the class of alarm that fires on a capability the user couldn't run anyway.
- **The nag-cap (`.28`/`.29`).** An advisory stops repeating after a few times per session; a defect that
  exempted the wrong lessons was caught by the *deeper* independent regrade and fixed, falsifiably.
- **Honesty fixes (`.30`/`.31`).** The wiring gate can no longer be satisfied by a comment; the test
  battery no longer cries "outage" when the model cache is merely cold.
- **Two cross-model duels recorded** (`docs/reviews/0040`, `0041`) — Fable 5 and GPT-5.6 each caught a
  real error in the other's position.

Fresh full suite, re-run 2026-07-24 (measured, not recalled): **1,665 passed · 1 failed · 224 todo.**
The one failure is not-mine and not-4.0 (a chunk-count claims-check against an unstaged KB edit of the
owner's — it clears when that edit is committed or reverted). Two failures from the previous stamp were
fixed this pass (the ADR status vocabulary predating the first Rejected ADR; a status line the parser
couldn't read), and one test (`forge-rerank-workers` case (c)) was observed to fail under full parallel
load and pass in isolation and on re-run — a flake worth pinning, named here rather than smoothed over.

## 7. Point-in-time, or continuous?

The owner asked this specifically, because it is the difference between a report and a live system.

| Pillar | Designed to be | What it is *today, live* |
|---|---|---|
| **Proactive** | **Continuous** — fires on every relevant state change via hooks, in-session | **Point-in-time** — you get advocacy only when you open the console, because the in-session delivery is on the un-flipped branch. Flipping the spine makes it continuous. |
| **Learning** | Mining is on-demand; **compounding is continuous** (nightly refresh promotes what won twice) | **Point-in-time** — the miner runs when invoked; the continuous compounding is unproven (nothing promoted yet) |
| **Self-implementation** | **Continuous** — the offensive audit re-runs and re-scores | **On-demand** — the audit runs when called; it has zero in-session call sites (honestly marked HELD, not falsely green) |

**The pattern is consistent and worth seeing clearly:** all three are *designed* continuous and are
*currently* point-in-time, and in every case the gap between the two is **deployment, not design.**

## 11. How it was tested *philosophically*

This is the point most systems skip, and it is the one the owner cares most about: not *does the code
pass*, but *does the implementation honor the stated intent.* We tested that adversarially, cross-model,
and it caught real philosophical errors — not just bugs:

- **"Nudge, not force" — tested by construction.** The chokepoint makes advisory speech *mechanically*
  incapable of refusing (exit 0, bytes owned); only a rule the user explicitly opted into blocking can
  refuse. The philosophy is enforced by the wire, not by good intentions.
- **"A lesson is the user's words, not the brain's advocacy" — caught by Fable 5.** A first design routed
  *all* unprompted speech, lessons included, through one advocacy dial. Fable 5 rejected it as a
  *category error* — collapsing two different consent classes — and the design was corrected to give
  lessons their own control. That is a philosophy test, adjudicated by an independent model, changing the
  build.
- **"Byte-ownership is enforceable" — caught by GPT-5.6.** The opposite error (claiming the seam couldn't
  truly own the bytes) was refuted by showing captured child stdio does exactly that. Both models
  corrected each other; the convergence is recorded *in* the ADR.
- **"A fixture you chose cannot falsify your choice" — claimed, caught violating its own principle, then
  actually closed.** The first build separated the *manifest* from the detector but let the *oracle* copy
  the detector's regex — identical circularity, one layer down. GPT-5.6-Sol caught it (the third
  philosophy error caught cross-model), the numbers were retracted, and the oracle was rebuilt structural
  + referential (`2c8ef4d`) so a wrong detector now *shows up* as a recall miss or a false alarm instead
  of being structurally invisible. The principle survived by being enforced against its own first
  implementation.

**Philosophical testing here means: the stated principle was turned into a mechanism, then an adversary
was paid to break the mechanism.** That happened, on the record, twice.

## 12. Are we aligned philosophically?

**Yes, on principle — and the remaining gaps are execution and deployment, not disagreement.** Where the
built system and the owner's stated philosophy line up:

- **Push, not pull** (the whole L3 thesis) · **nudge, not force** · **empty-first, honest-always** (no
  fabricated numbers on any surface) · **prove, don't assert** (status derived from artifacts) ·
  **measurements, not verdicts** · **when in doubt, defer to what rUv shipped** (we wire his promotion
  primitives, we don't hand-roll a stepchild).

Where **honest philosophical tension remains open** — worth the owner's eye, not swept away:

- **The advocacy dial's scope.** ADR-040 resolved *who owns the bytes*, but the dial is still presented as
  a single volume knob for behavior it doesn't entirely govern. The chokepoint makes this honest at the
  delivery layer; whether the *console copy* fully matches is a smaller open item.
- **Holding at a deploy-gated ceiling.** We are choosing to stop behind the fence rather than flip the
  spine ourselves. That is philosophically correct (the loop *should* prove itself on real data before the
  number changes) — but it means "done behind the fence" and "done" are deliberately different, and the
  owner should agree that's the right place to hold.
- **Goodhart risk on the five metrics.** Once metrics gate the release, they become targets. The fixture's
  separation-of-authorities design guards recall; the equivalent guard for precision needs the real ledger
  to exist first. Named, not yet closed.

**The alignment verdict: high on values, honest about the fact that the last stretch is deployment and
real-world data, which no amount of in-fence work can substitute for.**

## Plus — the four market-facing points

**What we promise the market (the honest version).** *"Your rUv/AI stack, watched — dormant capability
surfaced at the moment it's costing you, with a one-click fix you can undo; and lessons that compound
across every project instead of dying in one."* Not "4.0 magic." The diagnosis is the shippable half
today; the compounding is the promise we are still earning.

**What the user experience feels like.** *Today:* you open the console and see real faults with real
fixes — genuinely useful, but you have to go look. *After the spine flip:* the brain speaks inside your
session, once, at the relevant moment, with a one-action permanent mute — the difference between a
dashboard and a colleague who taps you on the shoulder and then leaves you alone.

**Why now.** Because the 21-day latency finding named the real problem, and this release is the first time
the machinery to destroy it exists end-to-end — and the moment it deploys, the outcome loop *starts
accumulating the data that makes everything after it measurable.* Waiting doesn't improve it; using it
does.

**What comes next (ordered by dependency).**
1. **Flip the installed spine `3.9.18` → `3.9.33`** (owner) — turns L3 from built to *felt*.
2. **Let the advocacy ledger accumulate** real offers/dismissals (owner) — turns precision from `null` to
   a number.
3. **Extend the fixture to all four capabilities** (in-fence) — recall on the full cohort.
4. **Promote one lesson and prove it survives `--update`** (in-fence) — closes the Learning loop once.
5. **Build L4 goal-inference** and **a real benchmark for evolution** — the two architectural pieces, each
   through the full ADR→DDD→duel→build→QE recipe.
6. **Reconcile the release channels** and **run a scoped Agentic-QE pass** before the number changes.
