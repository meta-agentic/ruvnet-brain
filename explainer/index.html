01 — The problem

"It works for me."

Ruv ships extraordinary infrastructure — RuVector alone is 1.58 million lines. But when you're not Ruv, it doesn't work for you. You point an AI at the repo, and it skims, guesses, and quietly argues against the architecture it doesn't understand.

WHY IT'S HARD

The ecosystem is enormous and deeply interconnected — 169 repos, an engine of 159 crates. No one holds it all in their head, so AI assistants summarize from memory and miss the decisive detail.

WHY CLAUDE DRIFTS

Its training prior whispers "use pgvector, use Pinecone — that exotic Rust thing probably isn't real." So it drifts off Ruv's architecture even after "reading" the docs. Knowledge alone doesn't fix behavior.

THE 15-MONTH PATTERN

Every prior attempt came up short: topical not deep (indexed summaries, not source), single-layer, and — worst — declared "done" by claim, never proven. "You said it was done; it was 30%."

WHY PEOPLE STAY STUCK

Their assistant confidently gives a wrong answer about RuVector, and they can't tell it's wrong. The gap between Ruv's intent and what gets built never closes.

02 — The failed assumption
"Point Claude at a deep repo and it'll keep reading until it finds the answer." — It doesn't.

It skims, falls back to training, and quits. So the fix isn't a KB the assistant can search — it's a brain that has already done the deep traversal and points the assistant to the exact line of code, removing its discretion to give up. That single inversion is the whole design.

05 — The proof

Measured, not claimed.

Every answer is graded by three independent vendors (OpenAI · DeepSeek · Llama) against the real source, with a poison rule: incomplete-but-not-wrong fails. It's run twice per repo — on a tuned set and a held-out (anti-overfit) set — so the score can't be gamed. This is the truth-telling harness that's been missing for 15 months.

What "REAL-USE 63–85" actually means

Three independent LLM graders — OpenAI gpt-4o-mini, DeepSeek, and Llama-3.3-70B — each score, 1–100, how well the top-5 retrieved real-source passages (synthesized the way an assistant reads them) answer each question. A separate mechanical check then confirms every cited file actually exists in the repo. 63–85 is the realistic band for multi-document synthesis across the five repos — and there were 0 hallucinated citations across every repo, on both the tuned and the held-out sets.

06 — Use it

One bundle. One line.

Get it on GitHub ↗ Download dist/ruvnet-brain.zip · 268 MB

Download the brain

Grab dist/ruvnet-brain.zip (268 MB, self-contained — all 5 core repos) from github.com/ruvnet; unzip into your project as kb/. Gitignore it — size doesn't matter when it has the intel.

Wire one line

Add the ruvnet-brain entry from mcp.snippet.json to .mcp.json — one tool, search_ruvnet, that searches every repo at once and returns whole source files labeled by repo. (Per-repo tools ship too, to scope to one.)

Just ask

Claude / Cursor / Codex now answer from Ruv's real code, with citations — and get ripped back when they drift. It rebuilds itself nightly, always date- and SHA-stamped.

# unzip the bundle into your project as kb/
unzip ruvnet-brain.zip -d kb/

# install the local reader, then add the ruvnet-brain entry to .mcp.json
cd kb && npm i
"ruvnet-brain": { "command": "node", "args": ["kb/forge-mcp-all.mjs"] }   # → the search_ruvnet tool

# …or just ask across every repo from the CLI right now
node forge-ask-all.mjs --dir . --q "how does ruflo persist memory?"
Is it safe to install?

Yes — the bundle is just local files (a vector index + the source text). The .mcp.json wires a local stdio server (forge-mcp-all.mjs) that only reads those local files and returns text. Embeddings run on your machine via @xenova/transformers. Nothing is sent anywhere — there are no network calls at query time; the search_ruvnet tool the assistant calls just runs a local vector search.
